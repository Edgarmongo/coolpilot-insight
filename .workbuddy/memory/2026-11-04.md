### 实测结论（重要）
- **抖音评论接口确实返回 cid**：19 条评论 19 个不同 cid，策略 100% `CID`。
  此前审计标为"C 级未验证"的假设已被证伪。
- 楼中楼：`reply_comment` 嵌套数组有效，19 条里含 6 条回复。
- 二次采集同一视频 → 仍 19 条，`ON DUPLICATE KEY UPDATE` + 双唯一键幂等成立。
- 匿名态仍是 3 页约 15~20 条封顶（本次 19 条）。

### 踩坑
1. **MyBatis-Plus 默认 NOT_NULL 策略**：`entity.setActiveFlag(null)` + `updateById` 不会写库。
   必须用 `LambdaUpdateWrapper.set(field, null)`。否则 `uk_video_active` 永远占着，
   该视频永久无法再采集。
2. **`/api/analysis/summary` 曾在拦截器 excludePathPatterns 里**：既允许未登录访问，
   又导致 RequestContext 为空 → 越权判定 403。已移除豁免。
3. 调度线程没有 HTTP 上下文：调用清洗前需显式注入 `RequestContext`（用任务发起人身份），
   否则统一授权会判为无权限。
4. `Py_Data` 是 COPY 进镜像，Datas 是 bind mount。改 Python 脚本必须重建 backend；
   临时验证脚本可放 `Py_Data/Datas/` 直接执行（实测有效）。

### 验证方式
- 接口冒烟 18 项全 200（搜索会因 curl 未编码中文报 400，非后端问题）。
- 真实浏览器（容器内 Chrome）渲染 /tasks /keywords /insight /reports /dashboard 均正常。
- AI 未配置 `DEEPSEEK_API_KEY` 时优雅降级：任务 FAILED、洞察返回 409、不消耗 token。

## DYP 能力原生移植（提交 46ee389）

用户明确否定了「跳转到 8088」的集成方式，要求把功能搬进来。已用本栈重写四项：

| DYP | 落地 | 关键实现 |
|---|---|---|
| 评论树 | `/api/comment/tree` + 评论页弹窗 | Java 组树，父节点缺失降级为一级 |
| 人工复核 | `analysis_review` + `/api/review/*` + 复核页 | before/after 快照；纠正覆盖 AI 结论 |
| PDF/Excel | Flask `/render/report` | reportlab CID 字体 + openpyxl 8 Sheet |
| 概览 | `/api/overview` + 运营概览页 | 跨视频聚合，空态有说明 |

**踩坑记录**：
1. `mysql -e` 在 Windows 下默认字符集非 utf8mb4，手工插中文会双重编码成乱码。
   验证数据必须加 `--default-character-set=utf8mb4`，否则会误判为链路 bug。
2. URL 里直接带中文参数会被 Tomcat 拒绝（`Invalid character found in request target`），
   curl 测试要 `urllib.parse.quote`。
3. MyBatis `Map<String,Object>` 上做 `merge(k, v, Long::sum)` 编译不过（Object 不能转 long）；
   统计容器要用 `Map<String,Long>`。
4. reportlab 的中文只需 `UnicodeCIDFont('STSong-Light')`，不必装字体文件。
5. 图表空白要显式给空态文案，否则用户会当成 bug。

**数据边界**：未配置 DEEPSEEK_API_KEY 时无法生成真实洞察；
报告页现有的一份是「（示例数据）」标注的演示报告，仅用于验证导出链路。
