### 03-01 现状审计（先做，确认无遗漏调用方）
产出 `docs/architecture/collection/SOURCE-03-AUDIT.md`。关键发现：

1. **Java 没有任何代码调用 collection-service 的 `/health` / `/v1/capabilities`**（全仓 grep）。
2. **生产采集走子进程，不走 HTTP**：`ProcessCollectionClient` → `python comment.py <id> <max>`；
   Java 读的是 **CSV 文件** `<aweme_id>.csv`；`DiscoveryService` 解析 `search.py` 的
   stdout 协议 `VIDEO|aweme_id|title|author|likes|url`。这三样都是硬契约。
3. **两个既有缺陷（如实披露，未在本任务修）**：
   - `AccountVerificationService.collectionReachable()` 探的 `app.collection-service-url`
     默认 `http://cpi-flask:5000`，而 `cpi-flask` 容器跑的是 **ai-service**，不是采集服务。
     因为两边 `/health` 都返回 200，一直没暴露。
   - **collection-service 的 Flask server 当前没有任何容器在跑**（compose 里没这个服务）。
4. `comment.py` 是**模块级脚本**（import 即启动浏览器采集），无法作为可 import 的真实函数，
   这是 03-02/03-03 的核心工作量。

### 关键设计决定（勿推翻）
1. **验证证据是数据不是代码**：能力声明一律从 `UNVERIFIED` 起步，
   只有 `app/registry/verification_evidence.json` 有真实运行记录才被提升为 `VERIFIED`。
2. **枚举一字未扩**：`NOT_LOADED` 是适配器加载状态，`INVALID_IMPLEMENTATION` 是诊断原因码，
   二者都不是 `implementationStatus` / `effectiveStatus`。
3. `STUB_PUBLIC` 不是平台接入（`platformScoped=false`，无 `sourceCode`），
   因此不产出 v1 平台文档，只出现在旧 `items` 与 `/v1/adapters` 里。

### 踩坑
- `docker cp collection-service/tests cpi-backend:/app/collection-service/tests`
  会**套一层**变成 `tests/tests/`，旧文件仍在导致测试假失败。要用 `docker cp src/. dest/`。
- `docker cp` 不会删目标里的旧文件，删 `__pycache__` 否则导入到旧模块。
