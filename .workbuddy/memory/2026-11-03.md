## 爬虫"采集不到评论"排查与修复（下午）

用户报：Chrome 中已登录抖音但采集不到评论。实际有 **3 个独立 bug**：

### Bug 1（主因）：搜索结果页链接解析不出来
用户贴的是 `/jingxuan/search/xxx?modal_id=<id>` 形式（搜索页点开视频后地址栏的样子），
旧正则 `r'/video/(\d+)'` 匹配不到 `modal_id=`，导致整串 URL 被当视频 ID，
浏览器打开的是**搜索页**而非 `/video/<id>` 详情页——两者评论区结构不同，抓不到数据包。
- 修复：`douyin_comment.py` 新增 `extract_video_id()`（纯数字 / /video/ / /note/ / /share/video/ / modal_id 五种形式），
  统一跳转 `/video/<id>`；Java `CollectUtils` 同步加 `MODAL_ID_PATTERN`。
- 验证：5/5 用例通过，用户那条真实链接从 0 条 → 12 条。

### Bug 2：进程泄漏锁死 Chrome profile
`douyin_comment.py` 没有 `dp.quit()`，每次运行残留 Chrome 进程 + `SingletonLock` 锁文件，
第二次运行必报"The browser connection fails... user folder does not conflict with the open browser"。
- 修复：`finally: dp.quit()`；`config_browser.py` 新增 `cleanup_stale_locks()`（只删属主 PID 已死的锁，跨平台 `_pid_alive`）。
- 验证：连续两次运行均成功，容器内 Chrome 进程数 0。

### Bug 3：采集状态查不到
`start` 存状态表用提取后的纯数字 key，`status` 查询却传原始输入（可能是整条 URL），key 对不上，
前端永远卡在"采集中…"。
- 修复：`CollectController.status` 用同一套 `extractVideoId` 提取 key。

### 关于登录态的结论
Windows 上的 Chrome 与容器内 Chrome 是**两个完全隔离的浏览器**，登录态不互通。
但**公开视频无需登录**即可采集（实测不登录也采到 15 条）。
登录态仅在视频有权限限制或触发风控时才需要；此时推荐本机采集 CSV 后放进 `Py_Data/Datas/`。

### 新增能力
- `preflight_check()`：采集前体检滚动容器，页面改版立刻报错（按维护笔记第五节建议实现）

## 地区分布地图省份着色（晚间）

用户要求"有数据的省份标记出颜色区分"。

### 根因
`RegionMap.vue` 缺少 **visualMap**（视觉映射）组件——没有它，ECharts 地图对所有省份
一律使用 `itemStyle.areaColor` 单一底色，值再大也不着色。
另有两个隐患：`loadMap()` 第二次 setOption 只传 map series，会覆盖掉 bar series。

### 修复
- 加 `visualMap`（continuous 型，浅青→深青色阶，min:0/max:最大评论数），左下角带「多/少」图例
- 无数据省份用浅灰底 `#F1F5F9` 突出对比
- **改为双独立 ECharts 实例**（左条形图 + 右地图），避免多 series 坐标系/grid 互相覆盖
  ——单实例方案实测会导致 canvas 宽高为 0、图表完全不渲染
- 条形与地图**共用同一色阶** `COLOR_RANGE`，条形按自身数值取色，深浅含义统一
- 地图 GeoJSON **本地化**到 `dy-frontend/public/geo/china.json`（569KB），
  优先本地加载、CDN 兜底 → 离线可用，不再依赖外网

### 踩坑
- ECharts 单实例放 bar+map 两个 series 时 grid/left/right 冲突，canvas 会渲染成 0 宽高
- 多次 setOption 会覆盖前一次的 grid/series，必须合并成一次调用或用双实例
