# CoolPilot Insight · 产品路线图（V1.0）

> 状态：产品基线
> 原则：**先把地基做厚，再谈场景与商业化**。每个阶段有明确的"交付标准"，达不到不进入下一阶段。
> 与代码现状的差距见 `PRODUCT-GAP-AUDIT.md`；本文只描述目标与门槛。

---

## 零、阶段划分总览

| 阶段 | 主题 | 一句话目标 | 进入条件 |
|---|---|---|---|
| 一 | 通用数据洞察基础能力 | 数据"采得稳、管得住、查得到" | — |
| 二 | AI 洞察分析能力 | 从数据到结论，且结论可解释 | 阶段一交付标准达成 |
| 三 | 足球行业研究场景 | 用真实行业验证商业价值 | 阶段二交付标准达成 |
| 四 | 商业化与行业扩展 | 换行业靠配置，交付可复制 | 阶段三产出可验证报告 |

**为什么这样排**：阶段三之前不碰"客户与收费"，因为**没有可验证的洞察，卖的是采集体力**。
阶段四之前不做多行业，因为**一个行业都没跑通，配置化就是空谈**。

## 阶段一 · 通用数据洞察基础能力（第一优先级）

### 目标

把"数据入口 → 采集 → 资产 → 检索"这条最基础的路修平，让后续所有分析有可靠的落脚点。

### 范围

| 子项 | 内容 | 现状 |
|---|---|---|
| 数据源管理 | 平台/数据源/能力/授权配置 | ✅ 已有（缺凭证加密、账号池） |
| 采集任务与执行状态 | 建任务、触发、重试、取消、断点 | ✅ 已有（能力接入不全） |
| 统一数据模型 | 内容/作者/评论的资产化 | ⚠️ 两套模型并存，未统一 |
| 数据检索与统计 | 按内容/时间/维度检索与聚合 | ⚠️ 有基础检索，无统一检索层 |
| 数据来源与质量追踪 | 每条记录的来源、采集时间、清洗结果 | ⚠️ 有部分字段，无质量视图 |

### 交付标准（可验证）

1. 任意一条评论，能回答"从哪个数据源、哪次任务、什么时间采的、经过哪次清洗"；
2. 采集失败有分类错误码，且能从任务页直接定位原因（不是"采集失败"四个字）；
3. 同一视频重复采集，`collected` 收敛到 0（去重记忆可靠）；
4. 能力准入覆盖**所有**执行入口，未验证能力无法被执行（含内部路径）。

> 现状：1 ⚠️（`source_item_id` 有，清洗结果未结构化）、2 ⚠️、3 ✅（2026-11-17 达成）、4 ✅（2026-11-17 达成）。

### 主要缺口

- 清洗结果无结构化摘要（只有 stdout）；
- 内容资产双模型（`video/comment` vs `ct_*`）未统一；
- `file_asset` 表空转，上传文件无资产记录；
- 关键词搜索能力不可用（平台风控，匿名态无法验证）。

## 阶段二 · AI 洞察分析能力

### 目标

让"数据 → 结论"这条路**可解释、可回溯**，而不是丢给模型一段文本。

### 范围

| 子项 | 内容 | 现状 |
|---|---|---|
| 内容分类与主题提取 | 主题聚类、标签体系 | ⚠️ 有 topics_json，无体系 |
| 用户需求识别 | 需求/痛点抽取与归类 | ⚠️ 有 painPoints/userNeed |
| 情感与观点分析 | 情感极性 + 观点抽取 | ⚠️ 只有情感极性 |
| 趋势与热点识别 | 时间序列、突增检测 | ⚠️ 只有 14 天趋势图 |
| AI 分析报告 | 结构化报告 + 证据引用 | ✅ 有 PDF/XLSX，证据链部分 |

### 交付标准

1. 每条 AI 结论带**证据锚点**（评论 id / 内容 id / 时间窗口），可点回原文；
2. 报告区分"数据事实 / 统计结果 / AI 推断 / 建议"四类表述，不混写；
3. 同一数据集重复分析，结论差异可解释（不是随机漂移）；
4. 分类与主题使用**可配置的 taxonomy**，而非硬编码在提示词里。

### 主要缺口

- 无观点抽取、无风险识别、无传播路径分析；
- 无聚类与关联分析（只有计数与 TopN）；
- `analysis_profile` 只有 1 条默认配置，且无 UI 管理；
- 无检索增强（无向量库、无 RAG），结论只能靠单次提示词。

## 阶段三 · 足球行业研究场景

### 目标

用**一个真实行业**检验通用平台是否成立，并产出可对外展示的研究成果。

### 范围

| 研究主题 | 产出 | 依赖 |
|---|---|---|
| 球迷需求研究 | 需求分类、痛点排序、场景建议 | 阶段二需求识别 |
| 周边商品市场分析 | 品类、价格带、评价痛点、机会点 | **商业洞察域（当前缺失）** |
| 足球内容传播分析 | 热点主题、传播表现、渠道差异 | 阶段二趋势识别 |
| 商业机会研究 | 赞助/活动/服务机会假设 | 上述三项 |
| 可验证研究报告 | 带来源、时间、局限说明的报告 | 阶段二报告能力 |

### 交付标准

1. 至少 3 份对外可展示的研究报告，每份都有明确的**数据范围与局限声明**；
2. 报告中的机会点能追溯到具体证据，且标注"假设/已验证"状态；
3. 全部内容遵守品牌与合规边界（不用队徽、不宣称授权、不做客户名单）；
4. 该场景**没有新增专属代码**——只新增 Profile 配置与报告模板。

> 第 4 条是这个阶段真正的验收点：如果为了足球场景写了一堆专用代码，
> 说明平台抽象失败了。

### 主要风险

- **商业洞察域从零开始**（商品/价格/竞品没有任何模型），是本阶段最大工作量；
- 足球垂类数据源的可采性受平台风控影响（关键词搜索已验证受阻）。

## 阶段四 · 商业化与行业扩展

### 目标

把"一个行业跑通"变成"换行业靠配置"，并形成可交付的商业形态。

### 范围

| 子项 | 内容 |
|---|---|
| 多行业研究 Profile | 电商 / 本地商业 / 企业服务 / 内容创作 |
| 客户工作空间 | 数据隔离、按客户授权、交付物管理 |
| 报告与数据产品交付 | 订阅式报告、按项目交付、数据导出 |
| 企业级分析服务 | 定制分析、API 接入、技术支持 |

### 交付标准

1. 新增一个行业，**只写配置**（Profile + taxonomy + 报告模板），不改核心代码；
2. 客户之间数据隔离可验证（不是靠前端过滤）；
3. 报告可复现：同一 Profile + 同一时间窗，重跑结论一致或差异可解释；
4. 商业化不依赖"采集量"计价。

### 前置条件（现在还不具备）

- 阶段一的资产模型统一；
- 阶段二的证据锚点与可配置 taxonomy；
- 独立的合规与数据处理说明（对外交付必需）。

## 每阶段的"不做清单"

| 阶段 | 明确不做 |
|---|---|
| 一 | 不做多行业、不做对外收费、不做实时告警 |
