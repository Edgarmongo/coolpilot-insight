# CoolPilot Insight — Product Roadmap

| 项 | 内容 |
|---|---|
| 产品 | CoolPilot Insight |
| 版本 | 1.0 |
| 日期 | 2026-11-18 |
| 代码基线 | `17e87e7` / Flyway V33 |

**总体目标**：在现有项目架构上逐步建设通用互联网数据洞察与商业增长平台，
优先形成"数据采集 → AI 洞察 → 研究报告"的完整闭环。

> 路线图是产品目标，**不是实现承诺**。每阶段开始前必须先核对现有代码，
> 优先复用已实现并验证的能力，再安排缺口开发（见 `PRODUCT-GAP-ANALYSIS.md`）。

---

## Phase 0：产品与架构基线

**目标**：确定产品定位、核心业务域、技术边界与架构约束。

**交付**

- `PRODUCT-VISION.md`
- `PRODUCT-ARCHITECTURE.md`
- `PRODUCT-ROADMAP.md`
- `PRODUCT-SOURCE-CONSISTENCY-REVIEW.md`（SOURCE 契约一致性审查）
- `CURRENT-IMPLEMENTATION-MAPPING.md`（当前实现映射）
- `PRODUCT-GAP-ANALYSIS.md`（当前实现与产品目标差距清单）

**验收**

- 产品定位明确。
- 模块职责明确。
- 不与现有 SOURCE 契约冲突。
- 不重复建设已有能力。

**状态**：🟡 本轮完成（2026-11-18），待独立复核。

## Phase 1：通用数据基础能力

**目标**：形成可靠的数据采集和统一数据资产基础。

**重点**

- 数据源管理
- 能力声明与核对
- 采集任务管理
- 采集执行状态
- 数据接收与去重
- 数据质量和来源追踪
- 采集错误分类与可观测性

**验收**

1. 至少一个合法数据源能够完成端到端采集。
2. 数据能够正确进入现有业务数据模型。
3. 失败能够定位、分类和追踪。
4. **不把未验证能力标记为可用。**

**当前完成度**（依据 `CURRENT-IMPLEMENTATION-MAPPING.md`）

| 验收项 | 状态 |
|---|---|
| 端到端采集 | ✅ 抖音视频评论，真实跑通并入库 |
| 进入业务数据模型 | ✅ `video` / `comment`（21 条评论 / 3 个视频） |
| 失败定位与分类 | ⚠️ 有 `errorCode` 与七类 `failure_type` 定义，但 Java 侧尚未逐项映射 |
| 未验证能力不得标记可用 | ✅ 准入闸门（2026-11-17） |

**剩余缺口**

- 清洗结果无结构化摘要（只有 stdout 原文回传）。
- 内容资产双模型（`video/comment` 与 `ct_*`）未统一。
- 上传文件无资产记录（`file_asset` 空转）。
- 关键词搜索能力被平台验证码阻断（`UNVERIFIED`）。

---

## Phase 2：AI 数据洞察

**目标**：让采集的数据产生**可解释**的分析结果。

**重点**

- 内容分类 / 主题提取
- 用户需求识别
- 情绪与观点分析
- 趋势分析
- 证据关联
- AI 分析报告

**验收**

1. 分析结果可以追溯到原始数据。
2. 明确区分模型推断与客观事实。
3. 分析结果具备时间和模型版本信息。

**当前完成度**

| 验收项 | 状态 |
|---|---|
| 可追溯到原始数据 | ⚠️ `analysis_evidence` 77 条，覆盖部分结论 |
| 区分推断与事实 | ⚠️ 报告有结构化章节，但缺"事实/推断"显式标注 |
| 含时间与模型版本 | ✅ `analysis_profile` 记录 provider/model/prompt/schema 版本 |

**剩余缺口**：观点抽取、风险识别、传播路径、聚类与关联分析、taxonomy 外置化、检索增强。

---

## Phase 3：足球行业研究场景

**目标**：用足球行业验证平台的商业洞察能力。

**研究主题**：球迷公开需求、商品市场需求、足球内容传播、体育品牌与赞助、观赛服务和活动市场。

**交付**

- 行业研究 Profile
- 需求洞察报告
- 商品市场研究报告
- 内容传播分析报告
- 商业机会研究报告

**验收**

1. 不依赖俱乐部内部系统或未经授权数据。
2. 研究结论具有公开证据。
3. 研究报告明确非官方性质。
4. **能够从通用平台能力生成研究结果**（不新增专属代码）。

> 第 4 条是本阶段真正的门槛：若为足球场景写了一堆专用代码，说明平台抽象失败。

**当前完成度**：❌ 未开始。商业洞察域**零实现**（无商品/价格/竞品模型），是本阶段最大工作量。

---

## Phase 4：商业化验证

**目标**：验证用户是否愿意为数据洞察和研究报告付费。

**方向**：专题研究报告、企业定制数据分析、市场与竞品监测、内容传播分析服务、行业数据洞察订阅。

**验收**

- 有明确目标客户。
- 有真实交付案例。
- 有可核算的交付成本。
- 有真实付费或明确采购意向。

**当前完成度**：❌ 未开始（依赖 Phase 3）。

---

## Phase 5：多行业扩展

**目标**：从足球扩展到更多行业。

**候选领域**：电商、本地商业、企业服务、内容创作、其他垂直行业。

**原则**：行业差异通过 Profile、指标、分析规则和报告模板实现，
**不为每个行业复制一套核心系统**。

**当前完成度**：❌ 未开始（依赖 Phase 3 的 Profile 机制成型）。

---

## 优先级规则

| 级别 | 覆盖范围 |
|---|---|
| **P0** | 数据来源合法性、SOURCE 契约、数据正确性、核心采集闭环 |
| **P1** | 统一数据资产、AI 分析、证据追踪、报告生成 |
| **P2** | 行业 Profile、商业洞察与商业化验证 |
| **P3** | 多行业扩展、订阅和规模化运营 |

---

## 不纳入当前阶段

- 未授权的俱乐部内部系统接入
- 未授权的票务、会员和支付系统接入
- 以公开账号构建营销名单
- 大规模多行业同时铺开
- 重复建设现有任务、账号和采集基础设施

---

## 调整原则

1. 路线图是产品目标，不是实现承诺。
2. 每阶段开始前先核对现有代码与依赖，复用已实现且已验证的能力。
3. 新增能力必须回答：它依赖哪个数据源能力？产出什么资产？结论如何回到证据？
4. 不得以产品规划替代实现证据；不得为了让路线图好看而降低 SOURCE 契约要求。
