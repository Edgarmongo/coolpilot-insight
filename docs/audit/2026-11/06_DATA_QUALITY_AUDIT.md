## 3. 数据可信度评估

### 3.1 一个值得注意的观察

**地区分布严重集中于辽宁（12/14 = 85.7%）**，而视频主题是"大连球迷 vs 云南球迷冲突"。

| 解读 | 合理性 |
|------|--------|
| 该视频为地域冲突话题，评论者多为事件当事地方 | ✅ 合理 |
| 抖音 `ip_label` 返回的是**用户 IP 归属地**，与用户常住地不完全一致 | ✅ 合理 |
| 采集偏差导致样本偏斜 | ⚠️ 无法排除（样本仅 14 条） |

**结论：数据本身自洽，但样本量不足以支撑任何分布性结论。**

**抽查结论（14 条中约 9 条存在可疑标注）**：

| 问题类型 | 表现 | 根因 |
|---------|------|------|
| **纯 @提及 被判积极** | 内容仅含 `@中国足协` 等提及，无实质情感 → SnowNLP 给高正分 | 短文本 + 无情感词时模型不稳定 |
| **疑问句被判积极** | "明年还来大连吗？" → 1 积极 | SnowNLP 对疑问句无专门处理 |
| **反讽/负面被判积极** | "必须重罚" 是诉求而非赞扬 | 无反讽识别 |

**根因分析**：

```python
# analysis_engine.py
score = SnowNLP(text.strip()).sentiments
if score > 0.6:   return 1
elif score < 0.4: return -1
return 0
```

- 使用 **SnowNLP 默认模型**（基于购物评论语料训练），**非抖音语料**
- 阈值 0.4/0.6 是硬编码，未经本项目数据调优
- **未使用** `sentiment_dict/` 中已有的 529 词词典（死代码）

**等级**：C（部分实现，存在明显限制）——这是**真实存在的准确性问题**，直接影响到「情感分析」功能可信度，以及后续基于情感的「用户需求/痛点识别」能力。

## 4. 数据流缺陷汇总

| 编号 | 缺陷 | 影响 | 等级 |
|------|------|------|------|
| Q-01 | 无 `cid` 字段 | 去重靠内容比对；无法识别评论更新；无唯一索引兜底 | P0 |
| Q-02 | 情感标注准确率偏低（约 60~70%，抽样估算） | 情感分析与下游 AI 结论失真 | P1 |
| Q-03 | `sentiment_dict/` 529 词词典完全未启用 | 已有资产浪费；词典未参与判定 | P2 |
| Q-04 | 无回复数据 | 楼中楼互动缺失 | P1 |
| Q-05 | 无视频元数据 | 无法做视频维度分析（作者、时长、热度） | P1 |
| Q-06 | 表情标签被剥离（`[哭哭]` 等） | 原始内容不可还原 | P3 |
| Q-07 | 抖音按热度排序，新评论易漏 | 增量不完整 | P1 |
| Q-08 | 匿名态仅 15 条上限 | 样本量天然受限 | C |
| Q-09 | 无原始数据表（只存加工后） | 无法重跑清洗、无法换算法重算 | P2 |
| Q-10 | `analysis_result` 与 `comment` 口径可能不一致 | 统计口径需核对 | P2 |
| Q-11 | 字段 COMMENT 中文乱码（3 个新列） | 可读性 | P3 |

## 6. 关于"样本不足"的明确声明

本次审计的数据库仅有 **14 条评论、1 个视频**。因此：

- ✅ **可下结论**：表结构、索引、唯一性约束、字段完整性、去重机制有效性、字段覆盖率
- ✅ **可下结论**：单条记录的标注质量（基于人工逐条比对）
- ❌ **不可下结论**：情感分布的真实比例、地区分布的代表性、算法在大样本下的准确率
- ❌ **不可下结论**：长期趋势、活跃度、用户构成

**建议**：在下一阶段开发前，**先采集 ≥3 个视频 × ≥200 条评论**（登录态）作为基线数据集，
否则任何统计口径的 AI 分析都无法验证效果。
